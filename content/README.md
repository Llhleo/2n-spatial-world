# 人物文案编辑

人物文案独立保存在 `people.json`。日常修改只改 `leaders` 中的 `name`（姓名）、`role`（角色）、`intro`（简介）；不要改 `id`、顺序、来源或 provenance。职责和简介可留空；没有可靠资料时不要补造内容。姓名不能为空，id 必须唯一。

`intro` 最多两行，用 JSON 的 `\n` 分行。手机实际换行仍需视觉验收：使用简短原义文案，不追加旧等级、Super 数量或贡献数字。显示只有姓名、角色、简介三个文字层级。成员名单 `members` 只保存已核实姓名，不附加虚构角色；人物庭院按名单原始顺序每 7 人一组，末组保留余数，空名单不生成空组。分组仅用于阅读排版，不表示排名、队伍或关系；管理层姓名出现在名单中仍保留。窄屏可拆成连续阅读子窗口，但不重排、删除或改写姓名。人物介绍仍只在 JSON 中编辑。

保存后先运行 `node --test tests/people-data.test.js`，再运行 `npm run build` 重新构建，按批准的流程发布才会更新网站。人物版本不自动覆盖冻结花朵版 GitHub Pages 快照。不改 main 或旧 Llhleo/2n。

未来文案增加汉字时需更新人物章节补充字体子集，不能替换前段已稳定字体，也不能通过手动改镜头迁就文案。竖屏重点文字应保留在中央 72% 宽、70% 高的阅读区域；超长文案先缩写并记录原义。
